## Approved visual and interaction direction

- **Measurement first:** price, resting liquidity, executed flow and exact inspection take precedence over decorative dashboards. Keep current native evidence distinct from historical selection and replay admission.
- **Neutral flagship:** refine existing Graphite (`dark-dull`) into neutral graphite/charcoal chrome with silver interaction states. Recommend it only when no saved theme choice exists. Apply the corresponding light treatment to Paper (`light-dull`). Retain Midnight (`dark`), Daylight (`light`), Forest (`forest`) and Neon (`futuristic`), as well as Graphite and Paper: six valid selectable identities, not a seventh theme or new storage IDs.
- **Functional color:** jade and rose identify sides/direction with redundant labels; amber identifies actionable caution. Keep focus, selection and scope understandable without color. Funding sign is not candle direction; unknown and missing evidence must not look like observed zero.
- **Compact, chart-centric desktop:** favor the plotted field, an expandable task rail, a slim command surface, compact instrument context and chart-integrated controls. Simultaneous native book and tape are the preferred desktop composition, not a mandate to discard responsive behavior or saved layouts.
- **Contextual detail:** a compact measurement readout with an expandable contextual inspector; an optional event docket closed by default. Neither should permanently displace the primary analytical field.
- **New-user defaults:** Market opens Price action; Microstructure opens Resting. Use compact density, with comfortable spacing where appropriate. These are presentation defaults, not permission to change native identity, source, replay cursor, financial scope or a restored choice. Their future placement is subject to the milestone boundary below, not blanket PR1 authorization.
- **Existing choices win:** preserve the configurable grid, all five presets (`balanced`, `price`, `liquidity`, `volatility`, `execution`), named layouts and their existing restoration scope. Saved choices take precedence over defaults; do not broaden what a named layout claims to restore. Execution remains an inspection preset, not live routing.

## Allowed PR1 and non-negotiable preservation

PR1 may refine the existing semantic tokens, neutral Graphite/Paper treatment, numeric typography, density, focus, control edges and shell frame/chrome. Reuse existing token names and component entry points. Styling existing command/chart controls does not authorize implementing a new command directory, destination system, resizable panel model or chart renderer.

Preserve:

- Existing React/native providers and one native owner per document, `NativeContext` / `useTerminal`, the existing session/display bridge and independent document sessions. No remount-driven source, cursor or state reset.
- Existing Lightweight Charts/native Canvas2D renderers, scheduling, successful-paint freshness, theme/DPR invalidation, pane visibility/freeze ownership and disposal. No continuous idle animation or second renderer/token engine.
- Native financial authority and exact decimal, epoch-nanosecond and ordinal strings through financial inputs, DTOs and exact readouts. Display coordinates or rounded labels never become prices, quantities, fees, funding, P&L or paper inputs. Preserve native units, explicit quote/settlement distinctions, source/generation/clock fences, unknowns and continuity incidents.
- Source, identity, replay ownership/cursor, range/follow/freeze, drafts and durable financial/capture state. Navigation, theme changes and rollback are not financial operations or incident recovery.
- `limit-orderbook.workspace.v1` payload version 2, `limit-orderbook.orderflow.ui-preferences` version 3, all four legacy `limit-orderbook.workspace.slots.v1` migrations, corrupt-storage handling and persistence-error behavior. No reset, destructive cleanup, new preference store or schema/version expansion.
- Existing APIs, database/recording formats, dependencies, native capacity and financial eligibility. Do not import the static B.2 controller, authored fixture data, specimen receipts, replay timers or renderers into production.

A code revert is presentation-only. It cannot delete recordings or ledgers, undo paper actions, restore an earlier cursor/accounting state, repeat an ambiguous mutation or reset browser preferences. If the visual direction cannot respect these boundaries, stop that portion for separate review rather than silently widening PR1.
